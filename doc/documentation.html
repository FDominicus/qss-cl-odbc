1. Overview

qss-cl-odbc is a thin layer over the ODBC API. It executes SQL with parameters and returns the results as Lisp lists; it does not generate SQL and has no object layer. It talks to any database with an ODBC driver. Tested with Microsoft Access (ACE driver), PostgreSQL (psqlODBC), MariaDB (Connector/ODBC) and SQLite (Christian Werner's sqliteodbc); see notes.html for the peculiarities of these drivers.

  • ODBC 3 handle API, diagnostics with SQLGetDiagRecW, all text through the Unicode (…W) functions.
  • Pointer-sized SQLLEN/SQLULEN: correct on 64-bit Windows and Unix.
  • Exact decimals (NUMERIC, DECIMAL, CURRENCY) as rationals; integers beyond 32 bit.
  • Dates as universal time without time zone shifts, also before 1900.
  • Streaming of large results (do-query, map-query).
  • The declarations of the ODBC API are generated from Microsoft's ODBC headers.

2. Installation and loading

qss-cl-odbc needs CFFI and babel (both in Quicklisp) and an ODBC driver manager:

SystemDriver manager
Windowsodbc32.dll, part of Windows. Configure data sources with the 64-bit “ODBC Data Sources” administrator when using a 64-bit Lisp.
Linux, BSDunixODBC (package unixodbc); qss-cl-odbc loads libodbc.so.2. Data sources in /etc/odbc.ini or ~/.odbc.ini.
macOSunixODBC or iODBC.

Put the directory where ASDF finds it (for Quicklisp: ~/quicklisp/local-projects/) and load it:

(ql:quickload :qss-cl-odbc)          ; or (asdf:load-system :qss-cl-odbc)

To use another driver manager library, set qss-cl-odbc:*odbc-library-file* before loading. Loading needs neither a C compiler nor the ODBC headers.

Coming from plain-odbc: qss-cl-odbc keeps the interface of plain-odbc; only the names differ. Load :qss-cl-odbc instead of :plain-odbc and write qss-cl-odbc: where you wrote plain-odbc:. Both can be loaded into the same Lisp. Two things behave differently from the original: decimals come as rationals (set *decimal-as-rational* to NIL for doubles), and errors carry ODBC 3 SQLSTATEs ("HY000", "42S02") instead of ODBC 2 ones ("S1000").

4. Connecting

connect-generic &rest attributesfunction

Connects with a connection string built from keyword/string pairs and returns an odbc-connection. (connect-generic :dsn "TESTDB" :uid "u" :pwd "p") uses DSN=TESTDB;UID=u;PWD=p. Without a DSN, name the driver: (connect-generic :driver "{Microsoft Access Driver (*.mdb, *.accdb)}" :dbq "C:/data/x.accdb"). The user is never prompted.

One attribute is not part of the connection string: :ansi-encoding (a keyword such as :utf-8 or :cp1252) sets the encoding of this connection's ANSI text, see section 12. An unknown encoding is an error before connecting.

connect dsn user passwordfunction

Same as (connect-generic :dsn dsn :uid user :pwd password).

close-connection connectionfunction

Rolls back an open transaction and closes the connection. It cannot be used again.

connection-ansi-encoding connectionaccessor

The ANSI encoding of the connection; setf-able.

use-bind-column connectionaccessor

T (default): result columns are bound (SQLBindCol), long ones read with SQLGetData. NIL: every column is read with SQLGetData. Needed for drivers that report a column too small, e.g. SQLite for BLOBs (reported as 255 bytes; bound reads are cut with a warning).

integer-as-bigint connectionaccessor

T: SQL_INTEGER columns are read as 64-bit integers. Set when connecting to SQLite, whose driver reports every integer expression as SQL_INTEGER and would otherwise cut values beyond 32 bit (see notes.html). NIL for other databases.

connect-sqlite file / connect-access file / connect-sql-server server database &optional user password / connect-oracle tns user password / connect-mysql server database user passwordfunctions

Shortcuts that connect through a template data source named by *default-sqlite-dsn*, *default-access-dsn*, … (the driver comes from the template, the file or server from the arguments). connect-sqlite uses the ANSI encoding UTF-8. Only connect-sqlite is covered by the tests.

5. Transactions

qss-cl-odbc switches autocommit off when connecting: every change needs (commit con), and close-connection rolls back.

Consequence: with autocommit off, even a SELECT opens a transaction that stays open until commit or rollback. SQLite then blocks writers on other connections; Access may show a second connection an old state. For connections that only read, keep autocommit on:

(let ((qss-cl-odbc:*connect-autocommit* t))
  (qss-cl-odbc:connect-generic :dsn "TESTDB"))
commit connection / rollback connectionfunctions

6. Executing SQL

All functions take the connection, the SQL text with ? for parameters, and the parameters (section 8). The * variants take the parameters as one list.

exec-query connection sql &rest parameters / exec-query*function

For a statement returning rows. For each result set two values: the rows (a list of lists) and the column names.

exec-update connection sql &rest parameters / exec-update*function

Returns the number of affected rows.

exec-command connection sql &rest parameters / exec-command*function

Returns the values of the output and input/output parameters as multiple values (none for a plain command).

exec-sql connection sql &rest parameters / exec-sql*function

The general form. Three values: the row count, a list of result sets (each a list of rows and column names), the list of output parameter values. A text with several statements returns several result sets where the driver supports it (PostgreSQL yes, SQLite no).

7. Row by row

do-query ((&rest variables) connection sql &rest parameters) &body bodymacro

Executes body once per row with the variables bound to the columns; only the current row is in memory. (return value) leaves early; the statement is freed also on return and on errors. Values: the number of rows and the column names (or the value of return). First result set only.

map-query function connection sql &rest parameters / map-query*function

Calls function with each row (a list). Values as do-query.

8. Parameters

A parameter is either a value, whose type qss-cl-odbc derives, or a list (value type [direction [arguments…]]); direction is :in (default), :out or :inout. Examples: ("abc" :string :in 100), (nil :integer :out), (12345/100 :decimal :in 19 2).

Long columns (LONGVARCHAR, LONGVARBINARY) are read with SQLGetData. ODBC allows SQLGetData only for columns after the last bound one unless the driver says otherwise; put long columns last, or set use-bind-column to NIL.

11. Dates and times

Dates are universal times. Databases store a wall clock time without zone; qss-cl-odbc maps it 1:1 to a universal time read as UTC (*date-time-zone* = 0). A local time zone would shift times on the days of the daylight saving changes (02:30 became 03:30).

encode-date year month day &optional hour minute secondfunction
decode-date universal-timefunction

Build and take apart date values with these, not with encode-universal-time (local zone). Both work before 1900 (Access stores a time of day as 1899-12-30). (setf *date-time-zone* nil) restores the old behaviour (local zone).

Other date types: *universal-time-to-date-dataype* (sic) converts read values, *date-datatype-to-universal-time* converts parameters, *date-type-predicate* recognizes your date objects for derived parameters.

12. Text and encodings

SQL text, column names, messages, strings and :unicode-string/:uclob parameters travel as UTF-16, independent of any code page. Characters beyond U+FFFF (e.g. emoji) are handled; lengths count UTF-16 units.

Only :string and :clob parameters use the ANSI interface (SQL_C_CHAR). Its encoding belongs to the driver, not to the operating system: Access on Windows wants the ANSI code page (:cp1252 in Western Europe), the SQLite ODBC driver always UTF-8. Each connection has its own (:ansi-encoding of connect-generic; default *ansi-encoding* at connect time: :cp1252 on Windows, :utf-8 elsewhere). Prefer plain strings; use :string only for drivers without Unicode.

13. Catalog functions

Wrappers of the ODBC catalog functions; NIL means “not given”. Results as exec-query; the columns are those of the ODBC function.

get-tables connection catalog schema table table-typefunction
get-columns connection catalog schema table columnfunction
get-primary-keys connection catalog schema tablefunction
get-foreign-keys connection pk-catalog pk-schema pk-table fk-catalog fk-schema fk-tablefunction

Not every driver implements all of them; then an sql-error is signalled and the connection stays usable. The tests print which ones the driver lacks.

14. Errors and warnings

A failed call signals sql-error. A call that succeeds with information (SQL_SUCCESS_WITH_INFO, e.g. data truncated) signals sql-warning with warn. Both are sql-conditions:

ReaderValue
sql-condition-messagethe messages of all diagnostic records, joined with “ | ”
sql-condition-stateSQLSTATE of the first record, e.g. "42S02"
sql-condition-native-errorerror number of the database
sql-condition-diagnosticsall records: list of (sqlstate native-error message)

Messages are read completely, also when longer than the first buffer. qss-cl-odbc asks with a buffer of 8190 characters first: psqlODBC splits long messages into several records counted in UTF-8 bytes and loses the text when the cut falls into an umlaut (see notes.html).

16. The ODBC layer and its generator

The constants, types, structures and function declarations of the ODBC API are not written by hand. src/odbc/odbc-api-generated.lisp is generated from Microsoft's ODBC headers in odbc-headers/ (MIT license, from microsoft/ODBC-Specification) by tools/generate-odbc-api.lisp, according to tools/odbc-api-spec.lisp. The generator is plain Lisp with a small C preprocessor; it reads the headers with and without _WIN64 and makes the types and constants that differ pointer-sized.

(asdf:load-system :qss-cl-odbc-generate)
(qss-cl-odbc-generate:generate)            ; after changing the spec
(asdf:load-system :qss-cl-odbc)            ; then the cross-check
(qss-cl-odbc-generate:check :cc "gcc")     ; with a C compiler

check compiles a program against the ODBC headers of the platform (unixODBC, iODBC, mingw-w64 under MSYS2, the Windows SDK) and compares every constant, the size and signedness of every type, the layout of every structure and every function prototype. Without a compiler it is skipped. The test generated-file-is-current ensures the shipped file matches the generator.

Constants can be left out in the spec (:exclude-constants), each group with its reason, which is also written into the generated file. Left out are SQL_SPEC_* (Microsoft's repository has the ODBC 4.0 draft value 4.00 regardless of ODBCVER) and SQL_OPT_TRACE_FILE_DEFAULT (each driver manager has its own default path).

Checked against three independent sets of headers (2026-10-14): Microsoft's, through the generator; unixODBC 2.3.12 with gcc under Linux; mingw-w64 with gcc under Windows (MSYS2). All types, structures, prototypes and used constants agree. The one remaining difference is unixODBC's SQL_API_SQLCANCELHANDLE (1022; Microsoft and mingw-w64: 1550), which qss-cl-odbc does not use.

The calls themselves (src/odbc/odbc-calls.lisp) check every return code and collect the diagnostics.

17. From C to Lisp

The same small program three times, in doc/examples/: connect, create a table, insert two rows through a prepared statement with parameters, read them back, read the diagnostics of a failing statement. All three print the same (SQLite, data source EXAMPLE):

1: Ana
2: Bo
error HY000: [SQLite]no such table: no_such_table (1)

(a) C, the ODBC API

Text through the Unicode functions as in qss-cl-odbc; every call checked. cc example.c -lodbc (Linux/macOS) or gcc example.c -lodbc32 (MSYS2).

/* qss-cl-odbc documentation, example (a): the ODBC API from C.
 *
 * Connects to a data source, creates a table, inserts two rows through a
 * prepared statement with parameters, reads them back, and shows the
 * diagnostics of a failing statement. Text goes through the Unicode (...W)
 * functions, as in qss-cl-odbc.
 *
 *   Linux/macOS:     cc example.c -lodbc -o example && ./example EXAMPLE
 *   Windows (MSYS2): gcc example.c -lodbc32 -o example.exe && ./example EXAMPLE
 *
 * Copyright (c) 2026 QSS / Friedrich Dominicus, BSD license (see license.txt)
 */
#if defined(_WIN32)
#include <windows.h>
#endif
#include <stdio.h>
#include <stdlib.h>
#include <sql.h>
#include <sqlext.h>

/* ASCII text -> SQLWCHAR (UTF-16); enough for this example */
static SQLWCHAR *w(const char *s)
{
    static SQLWCHAR buf[4][512];
    static int next = 0;
    SQLWCHAR *out = buf[next++ % 4];
    int i = 0;
    for (; s[i] && i < 511; i++) out[i] = (SQLWCHAR)(unsigned char)s[i];
    out[i] = 0;
    return out;
}

/* SQLWCHAR (UTF-16, ASCII part) -> char, for printing */
static const char *a(const SQLWCHAR *s)
{
    static char buf[4][1024];
    static int next = 0;
    char *out = buf[next++ % 4];
    int i = 0;
    for (; s[i] && i < 1023; i++) out[i] = s[i] < 128 ? (char)s[i] : '?';
    out[i] = 0;
    return out;
}

/* Every call is checked: on SQL_ERROR print all diagnostic records and stop. */
static void check(SQLRETURN rc, SQLSMALLINT type, SQLHANDLE handle, const char *what)
{
    if (rc == SQL_SUCCESS || rc == SQL_SUCCESS_WITH_INFO || rc == SQL_NO_DATA) return;
    SQLWCHAR state[6], message[1024];
    SQLINTEGER native;
    SQLSMALLINT length;
    for (SQLSMALLINT rec = 1;
         SQL_SUCCEEDED(SQLGetDiagRecW(type, handle, rec, state, &native, message, 1024, &length));
         rec++)
        fprintf(stderr, "%s: [%s] %s\n", what, a(state), a(message));
    exit(1);
}

int main(int argc, char **argv)
{
    const char *dsn = argc > 1 ? argv[1] : "EXAMPLE";
    char connection[256];
    SQLHENV env = SQL_NULL_HENV;
    SQLHDBC dbc = SQL_NULL_HDBC;
    SQLHSTMT stmt = SQL_NULL_HSTMT;

    /* environment and connection */
    check(SQLAllocHandle(SQL_HANDLE_ENV, SQL_NULL_HANDLE, &env), SQL_HANDLE_ENV, env, "env");
    check(SQLSetEnvAttr(env, SQL_ATTR_ODBC_VERSION, (SQLPOINTER)SQL_OV_ODBC3, 0),
          SQL_HANDLE_ENV, env, "version");
    check(SQLAllocHandle(SQL_HANDLE_DBC, env, &dbc), SQL_HANDLE_ENV, env, "dbc");
    snprintf(connection, sizeof connection, "DSN=%s", dsn);
    check(SQLDriverConnectW(dbc, NULL, w(connection), SQL_NTS, NULL, 0, NULL, SQL_DRIVER_NOPROMPT),
          SQL_HANDLE_DBC, dbc, "connect");
    check(SQLAllocHandle(SQL_HANDLE_STMT, dbc, &stmt), SQL_HANDLE_DBC, dbc, "stmt");

    /* a table */
    SQLExecDirectW(stmt, w("DROP TABLE IF EXISTS person"), SQL_NTS);
    check(SQLExecDirectW(stmt, w("CREATE TABLE person (id INTEGER PRIMARY KEY, name VARCHAR(50))"), SQL_NTS),
          SQL_HANDLE_STMT, stmt, "create");

    /* prepared INSERT with two parameters, executed twice */
    SQLINTEGER id;
    SQLWCHAR name[51];
    SQLLEN id_ind = 0, name_ind = SQL_NTS;
    check(SQLPrepareW(stmt, w("INSERT INTO person (id, name) VALUES (?, ?)"), SQL_NTS),
          SQL_HANDLE_STMT, stmt, "prepare");
    check(SQLBindParameter(stmt, 1, SQL_PARAM_INPUT, SQL_C_SLONG, SQL_INTEGER, 0, 0, &id, 0, &id_ind),
          SQL_HANDLE_STMT, stmt, "bind 1");
    check(SQLBindParameter(stmt, 2, SQL_PARAM_INPUT, SQL_C_WCHAR, SQL_WVARCHAR, 50, 0, name,
                           sizeof name, &name_ind),
          SQL_HANDLE_STMT, stmt, "bind 2");
    const char *names[] = {"Ana", "Bo"};
    for (int i = 0; i < 2; i++) {
        id = i + 1;
        SQLWCHAR *n = w(names[i]);
        int k = 0;
        for (; n[k]; k++) name[k] = n[k];
        name[k] = 0;
        check(SQLExecute(stmt), SQL_HANDLE_STMT, stmt, "insert");
    }
    check(SQLFreeStmt(stmt, SQL_RESET_PARAMS), SQL_HANDLE_STMT, stmt, "reset");
    check(SQLEndTran(SQL_HANDLE_DBC, dbc, SQL_COMMIT), SQL_HANDLE_DBC, dbc, "commit");

    /* SELECT, read row by row with SQLGetData */
    check(SQLExecDirectW(stmt, w("SELECT id, name FROM person ORDER BY id"), SQL_NTS),
          SQL_HANDLE_STMT, stmt, "select");
    while (SQLFetch(stmt) == SQL_SUCCESS) {
        SQLINTEGER rid;
        SQLWCHAR rname[51];
        SQLLEN ind;
        check(SQLGetData(stmt, 1, SQL_C_SLONG, &rid, 0, &ind), SQL_HANDLE_STMT, stmt, "id");
        check(SQLGetData(stmt, 2, SQL_C_WCHAR, rname, sizeof rname, &ind), SQL_HANDLE_STMT, stmt, "name");
        printf("%d: %s\n", (int)rid, a(rname));
    }
    check(SQLFreeStmt(stmt, SQL_CLOSE), SQL_HANDLE_STMT, stmt, "close");

    /* a failing statement: read its diagnostics */
    if (SQLExecDirectW(stmt, w("SELECT * FROM no_such_table"), SQL_NTS) == SQL_ERROR) {
        SQLWCHAR state[6], message[1024];
        SQLINTEGER native;
        SQLSMALLINT length;
        SQLGetDiagRecW(SQL_HANDLE_STMT, stmt, 1, state, &native, message, 1024, &length);
        printf("error %s: %s\n", a(state), a(message));
    }

    /* clean up */
    SQLExecDirectW(stmt, w("DROP TABLE person"), SQL_NTS);
    SQLEndTran(SQL_HANDLE_DBC, dbc, SQL_COMMIT);
    SQLFreeHandle(SQL_HANDLE_STMT, stmt);
    SQLDisconnect(dbc);
    SQLFreeHandle(SQL_HANDLE_DBC, dbc);
    SQLFreeHandle(SQL_HANDLE_ENV, env);
    return 0;
}

(b1) Common Lisp, line by line

The C program translated to the generated declarations: each %%sql-… is the C function of the same name, each $SQL_… the C constant, cffi:with-foreign-objects the local C variables. This is the layer qss-cl-odbc is built on.

;;; -*- Mode: Lisp -*-
;;; qss-cl-odbc documentation, example (b1): example.c translated line by line
;;; to Common Lisp, on the declarations generated from the ODBC headers
;;; (%%SQL-... = the C function, $SQL_... = the C constant). This is the level
;;; below qss-cl-odbc; normally you write example.lisp instead.
;;;
;;;   (asdf:load-system :qss-cl-odbc)
;;;   (load "doc/examples/example-raw.lisp")
;;;   (qss-cl-odbc::example-raw "EXAMPLE")
;;;
;;; Copyright (c) 2026 QSS / Friedrich Dominicus, BSD license (see license.txt)

(in-package :qss-cl-odbc)

(defun example-check (rc type handle what)
  "check() of example.c: on SQL_ERROR print all diagnostic records and stop."
  (unless (member rc (list $SQL_SUCCESS $SQL_SUCCESS_WITH_INFO $SQL_NO_DATA))
    (cffi:with-foreign-objects ((state :uint16 6) (native 'sql-integer)
                                (message :uint16 1024) (len 'sql-small-int))
      (loop for rec from 1
            while (member (%%sql-get-diag-rec-w type handle rec state native message 1024 len)
                          (list $SQL_SUCCESS $SQL_SUCCESS_WITH_INFO))
            do (format *error-output* "~A: [~A] ~A~%" what
                       (get-wide-string-nts state) (get-wide-string-nts message))))
    (error "~A failed" what)))

(defun example-raw (&optional (dsn "EXAMPLE"))
  (cffi:with-foreign-objects ((penv :pointer) (pdbc :pointer) (pstmt :pointer))
    ;; environment and connection
    (example-check (%%sql-alloc-handle $SQL_HANDLE_ENV (cffi:null-pointer) penv)
                   $SQL_HANDLE_ENV (cffi:null-pointer) "env")
    (let ((env (cffi:mem-ref penv :pointer)))
      (example-check (%%sql-set-env-attr env $SQL_ATTR_ODBC_VERSION (cffi:make-pointer $SQL_OV_ODBC3) 0)
                     $SQL_HANDLE_ENV env "version")
      (example-check (%%sql-alloc-handle $SQL_HANDLE_DBC env pdbc) $SQL_HANDLE_ENV env "dbc")
      (let ((dbc (cffi:mem-ref pdbc :pointer)))
        (with-wide-string (connection (format nil "DSN=~A" dsn))
          (example-check (%%sql-driver-connect-w dbc (cffi:null-pointer) connection $SQL_NTS
                                                 (cffi:null-pointer) 0 (cffi:null-pointer)
                                                 $SQL_DRIVER_NOPROMPT)
                         $SQL_HANDLE_DBC dbc "connect"))
        (example-check (%%sql-alloc-handle $SQL_HANDLE_STMT dbc pstmt) $SQL_HANDLE_DBC dbc "stmt")
        (let ((stmt (cffi:mem-ref pstmt :pointer)))
          (flet ((exec (sql what)
                   (with-wide-string (text sql)
                     (example-check (%%sql-exec-direct-w stmt text $SQL_NTS)
                                    $SQL_HANDLE_STMT stmt what))))
            ;; a table
            (with-wide-string (text "DROP TABLE IF EXISTS person")
              (%%sql-exec-direct-w stmt text $SQL_NTS))
            (exec "CREATE TABLE person (id INTEGER PRIMARY KEY, name VARCHAR(50))" "create")

            ;; prepared INSERT with two parameters, executed twice
            (cffi:with-foreign-objects ((id 'sql-integer) (name :uint16 51)
                                        (id-ind 'sql-len) (name-ind 'sql-len))
              (setf (cffi:mem-ref id-ind 'sql-len) 0
                    (cffi:mem-ref name-ind 'sql-len) $SQL_NTS)
              (with-wide-string (text "INSERT INTO person (id, name) VALUES (?, ?)")
                (example-check (%%sql-prepare-w stmt text $SQL_NTS) $SQL_HANDLE_STMT stmt "prepare"))
              (example-check (%%sql-bind-parameter stmt 1 $SQL_PARAM_INPUT $SQL_C_SLONG $SQL_INTEGER
                                                   0 0 id 0 id-ind)
                             $SQL_HANDLE_STMT stmt "bind 1")
              (example-check (%%sql-bind-parameter stmt 2 $SQL_PARAM_INPUT $SQL_C_WCHAR $SQL_WVARCHAR
                                                   50 0 name (* 2 51) name-ind)
                             $SQL_HANDLE_STMT stmt "bind 2")
              (loop for n in '("Ana" "Bo")
                    for i from 1
                    do (setf (cffi:mem-ref id 'sql-integer) i)
                       (%put-unicode-string name n) ; UTF-16 with terminating 0
                       (example-check (%%sql-execute stmt) $SQL_HANDLE_STMT stmt "insert")))
            (example-check (%%sql-free-stmt stmt $SQL_RESET_PARAMS) $SQL_HANDLE_STMT stmt "reset")
            (example-check (%%sql-end-tran $SQL_HANDLE_DBC dbc $SQL_COMMIT) $SQL_HANDLE_DBC dbc "commit")

            ;; SELECT, read row by row with SQLGetData
            (exec "SELECT id, name FROM person ORDER BY id" "select")
            (cffi:with-foreign-objects ((rid 'sql-integer) (rname :uint16 51) (ind 'sql-len))
              (loop while (= (%%sql-fetch stmt) $SQL_SUCCESS)
                    do (example-check (%%sql-get-data stmt 1 $SQL_C_SLONG rid 0 ind)
                                      $SQL_HANDLE_STMT stmt "id")
                       (example-check (%%sql-get-data stmt 2 $SQL_C_WCHAR rname (* 2 51) ind)
                                      $SQL_HANDLE_STMT stmt "name")
                       (format t "~D: ~A~%" (cffi:mem-ref rid 'sql-integer) (get-wide-string-nts rname))))
            (example-check (%%sql-free-stmt stmt $SQL_CLOSE) $SQL_HANDLE_STMT stmt "close")

            ;; a failing statement: read its diagnostics
            (with-wide-string (text "SELECT * FROM no_such_table")
              (when (= (%%sql-exec-direct-w stmt text $SQL_NTS) $SQL_ERROR)
                (cffi:with-foreign-objects ((state :uint16 6) (native 'sql-integer)
                                            (message :uint16 1024) (len 'sql-small-int))
                  (%%sql-get-diag-rec-w $SQL_HANDLE_STMT stmt 1 state native message 1024 len)
                  (format t "error ~A: ~A~%" (get-wide-string-nts state) (get-wide-string-nts message)))))

            ;; clean up
            (with-wide-string (text "DROP TABLE person")
              (%%sql-exec-direct-w stmt text $SQL_NTS))
            (%%sql-end-tran $SQL_HANDLE_DBC dbc $SQL_COMMIT)
            (%%sql-free-handle $SQL_HANDLE_STMT stmt)))
        (%%sql-disconnect dbc)
        (%%sql-free-handle $SQL_HANDLE_DBC dbc))
      (%%sql-free-handle $SQL_HANDLE_ENV env)))
  (values))

(b2) Common Lisp with qss-cl-odbc

The same with qss-cl-odbc: no handles, buffers or indicators; text is encoded and decoded; errors become sql-error conditions.

;;; -*- Mode: Lisp -*-
;;; qss-cl-odbc documentation, example (b2): what example.c does, with
;;; qss-cl-odbc. Errors are signalled as QSS-CL-ODBC:SQL-ERROR; handles,
;;; buffers, encodings and diagnostics are handled by qss-cl-odbc.
;;;
;;;   (asdf:load-system :qss-cl-odbc)
;;;   (load "doc/examples/example.lisp")
;;;   (example "EXAMPLE")
;;;
;;; Copyright (c) 2026 QSS / Friedrich Dominicus, BSD license (see license.txt)

(defun example (&optional (dsn "EXAMPLE"))
  (let ((con (qss-cl-odbc:connect-generic :dsn dsn)))
    (unwind-protect
         (progn
           ;; PostgreSQL answers with a notice when the table does not exist:
           ;; a QSS-CL-ODBC:SQL-WARNING, muffled here
           (handler-bind ((qss-cl-odbc:sql-warning #'muffle-warning))
             (qss-cl-odbc:exec-command con "DROP TABLE IF EXISTS person"))
           (qss-cl-odbc:exec-command con "CREATE TABLE person (id INTEGER PRIMARY KEY, name VARCHAR(50))")
           ;; prepared INSERT with two parameters, executed twice
           (qss-cl-odbc:with-prepared-statement
               (insert con "INSERT INTO person (id, name) VALUES (?, ?)"
                       '(:integer :in) '(:unicode-string :in 50))
             (loop for name in '("Ana" "Bo")
                   for id from 1
                   do (qss-cl-odbc:exec-prepared-update insert id name)))
           (qss-cl-odbc:commit con)
           ;; SELECT, row by row
           (qss-cl-odbc:do-query ((id name) con "SELECT id, name FROM person ORDER BY id")
             (format t "~D: ~A~%" id name))
           ;; a failing statement
           (handler-case (qss-cl-odbc:exec-query con "SELECT * FROM no_such_table")
             (qss-cl-odbc:sql-error (e)
               (format t "error ~A: ~A~%" (qss-cl-odbc:sql-condition-state e)
                       (qss-cl-odbc:sql-condition-message e))))
           (qss-cl-odbc:exec-command con "DROP TABLE person")
           (qss-cl-odbc:commit con))
      (qss-cl-odbc:close-connection con)))
  (values))

18. Tests

(asdf:load-system :qss-cl-odbc-test)
(qss-cl-odbc-test:run-all :dsn "TESTDB")   ; or (asdf:test-system :qss-cl-odbc)
                                              ; DSN also from QSS_ODBC_DSN

Unit tests need no database. The integration tests create and drop their own tables (qss_odbc_…) on the given data source; use an empty database. Driver peculiarities are features per database (e.g. :driver-rounds-doubles for SQLite); tests that do not apply are skipped with the reason. Cases are taken from the test suites of racket/db, pyodbc, psqlodbc and odbc-api. qss-patches.txt records the changes and the test runs.

The suite :chinook runs on the Chinook sample database and only reads. It contains the cases of the Chinook project's own test suite (row counts, last record of each table, eleven customers with non-ASCII names, invoice totals against their lines), with typed values: on databases with exact decimals the totals must match without rounding. Further cases cover Unicode parameters, row-by-row reading, sums beyond 32 bit, joins and foreign keys. Without a DSN it runs on the SQLite copy in src/test/chinook/ (driver from QSS_SQLITE_ODBC_DRIVER, default SQLite3); for other databases load the Chinook script and name the data source:

(qss-cl-odbc-test:run-chinook)                   ; the SQLite copy
(qss-cl-odbc-test:run-chinook :dsn "CHINOOK")    ; or QSS_CHINOOK_DSN; snake_case schemas work too

19. History and license

qss-cl-odbc is derived from plain-odbc, written by Roland Averkamp in 2005 (BSD license); David Owen adapted it to 64-bit Linux. Its lowest layer came from Paul Meurer's SQL/ODBC module (1999–2001). In 2026 QSS / Friedrich Dominicus moved it to ODBC 3.5, Unicode and 64-bit Windows, fixed a number of errors (see qss-patches.txt), added the test suite and replaced the lowest layer by declarations generated from Microsoft's ODBC headers; no code of the earlier lowest layer remains. On 2026-11-03 the QSS version was renamed from plain-odbc to qss-cl-odbc (system and package QSS-CL-ODBC) so that it can live next to the original; apart from the name the interface is unchanged.
